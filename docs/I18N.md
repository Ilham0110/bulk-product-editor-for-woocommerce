kalimat yang sama dipakai di lebih dari satu tempat.

kerjanya dan aturan yang harus diikuti saat menambah string baru.

## 1. Kenapa Terjemahan Tidak Akan Dimuat

### Yang sering disalahpahami

Banyak panduan menyuruh menambahkan ini:

```php
add_action('init', static function (): void {
    load_plugin_textdomain('bulk-product-editor-for-woocommerce', false, dirname(plugin_basename(__FILE__)) . '/languages');
});
```

**Untuk WordPress 4.6+ ini tidak diperlukan.** WordPress memuat terjemahan
secara *just-in-time*: saat `__()` dipanggil pertama kali,
`_load_textdomain_just_in_time()` mencari file terjemahan sendiri.

Yang dicari, berurutan (`class-wp-textdomain-registry.php:313`):

```
wp-content/languages/plugins/bulk-product-editor-for-woocommerce-{locale}.mo
wp-content/plugins/bulk-product-editor-for-woocommerce/{Domain Path}/bulk-product-editor-for-woocommerce-{locale}.mo
```

### Kenapa `Domain Path` wajib ada

Baris kedua bergantung pada header `Domain Path:`. Tanpa header itu WordPress
hanya menemukan terjemahan yang dipasang di `wp-content/languages/plugins/` —
terjemahan yang dibundel bersama plugin tidak akan pernah ditemukan.

Header plugin sudah memuatnya:

```php
/**
 * Plugin Name:  Bulk Product Editor for WooCommerce
 * Text Domain:  bulk-product-editor-for-woocommerce
 * Domain Path:  /languages
 */
```

Tidak ada kode PHP yang perlu ditulis — cukup header itu dan folder
`languages/`.

### Peringatan "triggered too early" di WordPress 6.7+

Sejak WordPress 6.7, memanggil `__()` sebelum action `init` memicu notice:

> Translation loading for the `bulk-product-editor-for-woocommerce` domain was triggered too early.

Plugin ini **aman** dari itu. String pertama dipanggil di `admin_menu`
(prioritas 99) dan `admin_enqueue_scripts` — keduanya jauh setelah `init`.

Yang perlu dihindari: jangan memanggil `__()` di level file, di
`plugins_loaded`, atau di dalam konstruktor yang jalan saat bootstrap.

❌ Terlalu awal:
```php
define('WCBULK_LABEL', __('Bulk Editor', 'bulk-product-editor-for-woocommerce'));   // level file
```

✅ Ditunda sampai dibutuhkan:
```php
private function label(): string
{
    return __('Bulk Editor', 'bulk-product-editor-for-woocommerce');
}
```

## 2. Aturan Penulisan String

### Text domain wajib literal

Fungsi terjemahan dibaca oleh **parser statis** (WP-CLI, Poedit) yang tidak
menjalankan PHP. Variabel tidak bisa dibaca parser.

❌ Tidak akan pernah masuk file `.pot`:
```php
__('Save', $this->textdomain);
__('Save', TEXTDOMAIN);
__($label, 'bulk-product-editor-for-woocommerce');        // string-nya juga harus literal
```

✅ Benar:
```php
__('Save', 'bulk-product-editor-for-woocommerce');
```

Plugin ini konsisten — nol pelanggaran di 211 pemanggilan. Pertahankan.

### Pilih fungsi yang tepat

| Fungsi | Untuk apa |
|---|---|
| `__()` | ambil string, kembalikan |
| `_e()` | ambil string, langsung cetak |
| `esc_html__()` | ambil + escape, kembalikan |
| `esc_html_e()` | ambil + escape, cetak |
| `esc_attr__()` / `esc_attr_e()` | untuk nilai atribut HTML |
| `_n()` | bentuk tunggal/jamak |
| `_x()` | string ambigu yang perlu konteks |

Di view, gunakan varian yang sudah meng-escape — itu pola yang dipakai
`admin-page.php`:

```php
<?php esc_html_e('Columns', 'bulk-product-editor-for-woocommerce'); ?>
placeholder="<?php esc_attr_e('Name or SKU...', 'bulk-product-editor-for-woocommerce'); ?>"
```

### Placeholder, bukan penyambungan

❌ Tidak bisa diterjemahkan — urutan kata berbeda di tiap bahasa:
```php
echo __('Deleted ', 'bulk-product-editor-for-woocommerce') . $count . __(' products', 'bulk-product-editor-for-woocommerce');
```

✅ Satu string utuh dengan placeholder:
```php
sprintf(
    /* translators: %d: jumlah produk */
    __('Deleted %d products.', 'bulk-product-editor-for-woocommerce'),
    $count
);
```

**Komentar `/* translators: */` wajib** kalau ada placeholder. Penerjemah hanya
melihat string, bukan kodenya — tanpa komentar, mereka tidak tahu `%d` itu apa.
Komentar harus tepat di baris sebelum pemanggilan fungsi.

Untuk lebih dari satu placeholder, pakai penomoran agar urutannya bisa diubah:

```php
sprintf(
    /* translators: 1: SKU produk, 2: pesan error */
    __('Product %1$s failed: %2$s', 'bulk-product-editor-for-woocommerce'),
    $sku,
    $error
);
```

Tanpa penomoran, penerjemah tidak bisa menukar urutan — dan di banyak bahasa
urutannya memang harus ditukar.

### Bentuk jamak

Plugin ini sudah memakainya dengan benar:

```php
sprintf(
    _n('%d product updated.', '%d products updated.', $updated, 'bulk-product-editor-for-woocommerce'),
    $updated
);
```

Perhatikan `$updated` muncul dua kali — sekali untuk `_n()` memilih bentuk,
sekali untuk `sprintf()` mengisi placeholder. Ini bukan kesalahan.

Jangan menghitung jamak secara manual:

❌ Salah — banyak bahasa punya lebih dari dua bentuk jamak:
```php
echo $count === 1 ? __('1 product', …) : sprintf(__('%d products', …), $count);
```

## 3. String JavaScript

### Pola yang dipakai

String untuk JS dikumpulkan di `i18n_strings()` lalu dikirim lewat
`wp_localize_script()`:

```php
private function i18n_strings(): array
{
    return [
        'confirm_save' => __('Save changes for {count} product(s)?', 'bulk-product-editor-for-woocommerce'),
        'saving'       => __('Saving...', 'bulk-product-editor-for-woocommerce'),
        // …
    ];
}
```

Dipakai di JS:
```js
confirm(WCB.i18n.confirm_save.replace('{count}', ids.length))
```

Placeholder memakai `{count}`, bukan `%d`, karena JavaScript tidak punya
`sprintf`. Ini konvensi internal plugin — 11 string memakainya. Konsisten,
jadi pertahankan.

### Seluruh string JS kini lewat `i18n_strings()`

Sempat ada sembilan string yang di-hardcode di `admin.js` — konfirmasi discard,
alert Quick Apply, prompt nama view, dan sejenisnya. Semuanya sudah dipindah,
bersama lima yang ditemukan menyusul: label jumlah terpilih di modal bulk edit,
pesan staging, dua state tombol Quick Add, dan pesan sesi kedaluwarsa.

Pemeriksaan cepat bahwa tidak ada yang menyelinap kembali:

```bash
grep -nE "\.text\('[A-Z]|alert\('[A-Z]|confirm\('[A-Z]|prompt\('[A-Z]" assets/admin.js
```

Harus kosong. Untuk memastikan setiap key yang dipakai JS benar-benar ada di
PHP:

```bash
for k in $(grep -oE "i18n\.[a-z_]+" assets/admin.js | sed 's/i18n\.//' | sort -u); do
  grep -q "'$k'" bulk-product-editor-for-woocommerce.php || echo "HILANG di PHP: $k"
done
```

Placeholder JS memakai `{count}`, bukan `%d` — JavaScript tidak punya
`sprintf`. Isi dengan `.replace('{count}', n)`.

### Kenapa bukan `wp_set_script_translations()`

WordPress punya API khusus terjemahan JS, tapi hanya bekerja untuk script yang
di-*build* dengan `@wordpress/i18n` dan menghasilkan file `.json` per-script.
Plugin ini tanpa build step ([ADR 0002](adr/0002-tanpa-build-step.md)), jadi
pola `wp_localize_script` adalah pilihan yang tepat di sini.

## 4. Label Kolom — sudah diterjemahkan

`const COLUMNS` menyimpan label sebagai string biasa:

```php
private const COLUMNS = [
    'thumb'         => ['label' => 'Image',         'default' => true],
    'name'          => ['label' => 'Product Name',  'default' => true],
    'regular_price' => ['label' => 'Regular Price', 'default' => true, 'editable' => true],
    // …30 kolom
];
```

Ini **tidak bisa** diperbaiki dengan membungkus `__()` di tempatnya — konstanta
PHP tidak boleh berisi pemanggilan fungsi.

❌ Fatal error:
```php
private const COLUMNS = [
    'thumb' => ['label' => __('Image', 'bulk-product-editor-for-woocommerce')],   // tidak boleh
];
```

Solusinya: terjemahkan saat dibaca, bukan saat didefinisikan.

```php
/** Label kolom, diterjemahkan. Dipanggil saat enqueue, jauh setelah init. */
private function column_labels(): array
{
    return [
        'thumb'         => __('Image', 'bulk-product-editor-for-woocommerce'),
        'name'          => __('Product Name', 'bulk-product-editor-for-woocommerce'),
        'regular_price' => __('Regular Price', 'bulk-product-editor-for-woocommerce'),
        // …
    ];
}
```

Lalu gabungkan saat mengirim ke JS:

```php
$labels  = $this->column_labels();
$columns = [];

foreach (self::COLUMNS as $key => $meta) {
    $columns[$key] = ['label' => $labels[$key] ?? $meta['label']] + $meta;
}
```

`?? $meta['label']` menjaga agar kolom yang lupa didaftarkan tetap punya label,
bukan menampilkan kosong.

Itulah yang dilakukan `translated_columns()`, dipakai oleh `enqueue_assets()`
maupun `wc_bulk_get_columns()` sehingga modal Columns dan payload preload
selalu sepakat.

### Dua set label, sengaja berbeda

Header tabel memakai label yang lebih pendek daripada modal Columns — sebuah
header harus muat di kolom sempit, sementara modal punya ruang untuk nama
lengkap:

| Kolom | `column_labels()` (modal) | `column_headers()` (tabel) |
|---|---|---|
| `regular_price` | Regular Price | Price |
| `manage_stock` | Manage Stock | Mgmt |
| `downloadable` | Downloadable | DL |

Keduanya dikirim terpisah: `all_columns` dan `col_headers`. Singkatan seperti
"Mgmt" dan "DL" diberi komentar `/* translators: */` karena penerjemah tidak
bisa menebaknya dari teks saja.

Tiga label tetap di sisi JS dan **tidak** diterjemahkan: `cb` (markup checkbox
select-all), `thumb` (kosong), dan `featured` (simbol ★). Ketiganya bukan teks.

## 5. Membuat File `.pot`

`.pot` adalah template berisi semua string yang bisa diterjemahkan. Penerjemah
memakainya untuk membuat `.po` (terjemahan) yang lalu dikompilasi jadi `.mo`.

Dengan WP-CLI (terpasang di `C:\laragon\bin\wp-cli`):

```bash
wp i18n make-pot . languages/bulk-product-editor-for-woocommerce.pot --domain=bulk-product-editor-for-woocommerce --exclude=docs,tests
```

Alternatif tanpa CLI: **Poedit** dapat memindai folder plugin dan menghasilkan
`.pot` yang setara.

Alur kerjanya:

```
kode  →  .pot  →  .po (per bahasa)  →  .mo (dikompilasi)
             penerjemah          otomatis/Poedit
```

Penamaan file wajib mengikuti pola `{textdomain}-{locale}.mo`:

```
languages/
├── bulk-product-editor-for-woocommerce.pot            template
├── bulk-product-editor-for-woocommerce-id_ID.po       terjemahan Indonesia (sumber)
└── bulk-product-editor-for-woocommerce-id_ID.mo       hasil kompilasi ← ini yang dimuat WordPress
```

`.gitignore` plugin ini sudah memblokir `*.mo` — file itu hasil kompilasi dan
bisa dibuat ulang dari `.po`. `.po` dan `.pot` tetap masuk repo.

Locale Indonesia adalah `id_ID`. Daftar lengkap ada di
`wp-includes/l10n.php` dan situs translate.wordpress.org.
