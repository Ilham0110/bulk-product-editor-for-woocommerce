# Internasionalisasi (i18n)

Plugin ini punya **136 string** yang dibungkus fungsi terjemahan — 45 di PHP
utama, 91 di view. Semuanya memakai text domain literal `'wc-bulk-editor'`,
dan itu sudah benar.

Tapi **tidak satu pun akan pernah diterjemahkan**, karena tiga hal yang hilang.
Dokumen ini menjelaskan apa yang kurang, kenapa penting, dan cara memperbaikinya.

---

## Keadaan Saat Ini

| Aspek | Status |
|---|---|
| Text domain literal `'wc-bulk-editor'` | ✅ konsisten, nol pelanggaran |
| `__()`, `_e()`, `esc_html__()` dipakai | ✅ 136 string |
| `_n()` untuk bentuk jamak | ✅ dipakai (1 tempat) |
| Header `Text Domain:` | ✅ ada |
| Header `Domain Path:` | ❌ **tidak ada** |
| Folder `languages/` | ❌ **tidak ada** |
| File `.pot` | ❌ **tidak ada** |
| String JS lewat `i18n_strings()` | ⚠️ sebagian — 9 string hardcoded |
| Label kolom (`const COLUMNS`) | ❌ hardcoded Inggris |

## 1. Kenapa Terjemahan Tidak Akan Dimuat

### Yang sering disalahpahami

Banyak panduan menyuruh menambahkan ini:

```php
add_action('init', static function (): void {
    load_plugin_textdomain('wc-bulk-editor', false, dirname(plugin_basename(__FILE__)) . '/languages');
});
```

**Untuk WordPress 4.6+ ini tidak diperlukan.** WordPress memuat terjemahan
secara *just-in-time*: saat `__()` dipanggil pertama kali,
`_load_textdomain_just_in_time()` mencari file terjemahan sendiri.

Yang dicari, berurutan (`class-wp-textdomain-registry.php:313`):

```
wp-content/languages/plugins/wc-bulk-editor-{locale}.mo
wp-content/plugins/wc-bulk-editor/{Domain Path}/wc-bulk-editor-{locale}.mo
```

### Masalah sebenarnya

Baris kedua bergantung pada header `Domain Path:` — dan header itu **tidak ada**
di `wc-bulk-editor.php`.

Tanpa `Domain Path`, WordPress hanya akan menemukan terjemahan yang dipasang di
`wp-content/languages/plugins/`. Terjemahan yang dibundel bersama plugin tidak
akan pernah ditemukan.

### Perbaikan

Tambahkan satu baris ke header plugin:

```php
/**
 * Plugin Name:  WooCommerce Bulk Product Editor
 * Text Domain:  wc-bulk-editor
 * Domain Path:  /languages          ← tambahkan ini
 */
```

Lalu buat folder `languages/`. Tidak ada kode PHP yang perlu ditulis.

### Peringatan "triggered too early" di WordPress 6.7+

Sejak WordPress 6.7, memanggil `__()` sebelum action `init` memicu notice:

> Translation loading for the `wc-bulk-editor` domain was triggered too early.

Plugin ini **aman** dari itu. String pertama dipanggil di `admin_menu`
(prioritas 99) dan `admin_enqueue_scripts` — keduanya jauh setelah `init`.

Yang perlu dihindari: jangan memanggil `__()` di level file, di
`plugins_loaded`, atau di dalam konstruktor yang jalan saat bootstrap.

❌ Terlalu awal:
```php
define('WCBULK_LABEL', __('Bulk Editor', 'wc-bulk-editor'));   // level file
```

✅ Ditunda sampai dibutuhkan:
```php
private function label(): string
{
    return __('Bulk Editor', 'wc-bulk-editor');
}
```

## 2. Aturan Penulisan String

### Text domain wajib literal

Fungsi terjemahan dibaca oleh **parser statis** (WP-CLI, Poedit) yang tidak
menjalankan PHP. Variabel tidak bisa dibaca parser.

❌ Tidak akan pernah masuk file `.pot`:
```php
__('Save', $this->textdomain);
__('Save', TEXTDOMAIN);
__($label, 'wc-bulk-editor');        // string-nya juga harus literal
```

✅ Benar:
```php
__('Save', 'wc-bulk-editor');
```

Plugin ini konsisten — nol pelanggaran di 136 string. Pertahankan.

### Pilih fungsi yang tepat

| Fungsi | Untuk apa |
|---|---|
| `__()` | ambil string, kembalikan |
| `_e()` | ambil string, langsung cetak |
| `esc_html__()` | ambil + escape, kembalikan |
| `esc_html_e()` | ambil + escape, cetak |
| `esc_attr__()` / `esc_attr_e()` | untuk nilai atribut HTML |
| `_n()` | bentuk tunggal/jamak |
| `_x()` | string ambigu yang perlu konteks |

Di view, gunakan varian yang sudah meng-escape — itu pola yang dipakai
`admin-page.php`:

```php
<?php esc_html_e('Columns', 'wc-bulk-editor'); ?>
placeholder="<?php esc_attr_e('Name or SKU...', 'wc-bulk-editor'); ?>"
```

### Placeholder, bukan penyambungan

❌ Tidak bisa diterjemahkan — urutan kata berbeda di tiap bahasa:
```php
echo __('Deleted ', 'wc-bulk-editor') . $count . __(' products', 'wc-bulk-editor');
```

✅ Satu string utuh dengan placeholder:
```php
sprintf(
    /* translators: %d: jumlah produk */
    __('Deleted %d products.', 'wc-bulk-editor'),
    $count
);
```

**Komentar `/* translators: */` wajib** kalau ada placeholder. Penerjemah hanya
melihat string, bukan kodenya — tanpa komentar, mereka tidak tahu `%d` itu apa.
Komentar harus tepat di baris sebelum pemanggilan fungsi.

Untuk lebih dari satu placeholder, pakai penomoran agar urutannya bisa diubah:

```php
sprintf(
    /* translators: 1: SKU produk, 2: pesan error */
    __('Product %1$s failed: %2$s', 'wc-bulk-editor'),
    $sku,
    $error
);
```

Tanpa penomoran, penerjemah tidak bisa menukar urutan — dan di banyak bahasa
urutannya memang harus ditukar.

### Bentuk jamak

Plugin ini sudah memakainya dengan benar:

```php
sprintf(
    _n('%d product updated.', '%d products updated.', $updated, 'wc-bulk-editor'),
    $updated
);
```

Perhatikan `$updated` muncul dua kali — sekali untuk `_n()` memilih bentuk,
sekali untuk `sprintf()` mengisi placeholder. Ini bukan kesalahan.

Jangan menghitung jamak secara manual:

❌ Salah — banyak bahasa punya lebih dari dua bentuk jamak:
```php
echo $count === 1 ? __('1 product', …) : sprintf(__('%d products', …), $count);
```

## 3. String JavaScript

### Pola yang dipakai

String untuk JS dikumpulkan di `i18n_strings()` lalu dikirim lewat
`wp_localize_script()`:

```php
private function i18n_strings(): array
{
    return [
        'confirm_save' => __('Save changes for {count} product(s)?', 'wc-bulk-editor'),
        'saving'       => __('Saving...', 'wc-bulk-editor'),
        // …
    ];
}
```

Dipakai di JS:
```js
confirm(WCB.i18n.confirm_save.replace('{count}', ids.length))
```

Placeholder memakai `{count}`, bukan `%d`, karena JavaScript tidak punya
`sprintf`. Ini konvensi internal plugin — 11 string memakainya. Konsisten,
jadi pertahankan.

### Masalah: 9 string hardcoded

Sembilan string di `admin.js` **tidak** lewat `i18n_strings()` dan karenanya
tidak bisa diterjemahkan:

| Baris | String |
|---|---|
| 179 | `'Discard all changes?'` |
| 1149 | `'Select a field first.'` |
| 1197 | `'Applied to all loaded products.'` |
| 1268 | `'Changes discarded.'` |
| 1415 | `'Select at least one field to change.'` |
| 1418 | `'Apply changes to ' + ids.length + ' product(s)?'` |
| 1572 | `'Product name is required.'` |
| 1610 | `'No products to export.'` |
| 1724 | `'Delete this view?'` |

Perbaikannya: tambahkan ke `i18n_strings()` di PHP, lalu ganti di JS.

```php
// wc-bulk-editor.php — i18n_strings()
'confirm_discard'   => __('Discard all changes?', 'wc-bulk-editor'),
'select_field'      => __('Select a field first.', 'wc-bulk-editor'),
'quick_applied'     => __('Applied to all loaded products.', 'wc-bulk-editor'),
'changes_discarded' => __('Changes discarded.', 'wc-bulk-editor'),
'select_one_field'  => __('Select at least one field to change.', 'wc-bulk-editor'),
'confirm_bulk_edit' => __('Apply changes to {count} product(s)?', 'wc-bulk-editor'),
'product_name_req'  => __('Product name is required.', 'wc-bulk-editor'),
'no_export'         => __('No products to export.', 'wc-bulk-editor'),
'confirm_del_view'  => __('Delete this view?', 'wc-bulk-editor'),
```

```js
// admin.js
if (confirm(WCB.i18n.confirm_discard)) s.discardAll();
alert(WCB.i18n.select_field);
if (!confirm(WCB.i18n.confirm_bulk_edit.replace('{count}', ids.length))) return;
```

Perhatikan baris 1418 — string yang disambung dengan `+` harus diubah jadi
placeholder `{count}`, mengikuti pola yang sudah ada.

### Kenapa bukan `wp_set_script_translations()`

WordPress punya API khusus terjemahan JS, tapi hanya bekerja untuk script yang
di-*build* dengan `@wordpress/i18n` dan menghasilkan file `.json` per-script.
Plugin ini tanpa build step ([ADR 0002](adr/0002-tanpa-build-step.md)), jadi
pola `wp_localize_script` adalah pilihan yang tepat di sini.

## 4. Label Kolom Belum Diterjemahkan

`const COLUMNS` menyimpan label sebagai string biasa:

```php
private const COLUMNS = [
    'thumb'         => ['label' => 'Image',         'default' => true],
    'name'          => ['label' => 'Product Name',  'default' => true],
    'regular_price' => ['label' => 'Regular Price', 'default' => true, 'editable' => true],
    // …29 kolom
];
```

Ini **tidak bisa** diperbaiki dengan membungkus `__()` di tempatnya — konstanta
PHP tidak boleh berisi pemanggilan fungsi.

❌ Fatal error:
```php
private const COLUMNS = [
    'thumb' => ['label' => __('Image', 'wc-bulk-editor')],   // tidak boleh
];
```

Solusinya: terjemahkan saat dibaca, bukan saat didefinisikan.

```php
/** Label kolom, diterjemahkan. Dipanggil saat enqueue, jauh setelah init. */
private function column_labels(): array
{
    return [
        'thumb'         => __('Image', 'wc-bulk-editor'),
        'name'          => __('Product Name', 'wc-bulk-editor'),
        'regular_price' => __('Regular Price', 'wc-bulk-editor'),
        // …
    ];
}
```

Lalu gabungkan saat mengirim ke JS:

```php
$labels  = $this->column_labels();
$columns = [];

foreach (self::COLUMNS as $key => $meta) {
    $columns[$key] = ['label' => $labels[$key] ?? $meta['label']] + $meta;
}
```

`?? $meta['label']` menjaga agar kolom yang lupa didaftarkan tetap punya label,
bukan menampilkan kosong.

Ini pekerjaan yang cukup besar (29 kolom) dan tidak mendesak selama toko
berbahasa Inggris. Catat sebagai utang, jangan dikerjakan setengah.

## 5. Membuat File `.pot`

`.pot` adalah template berisi semua string yang bisa diterjemahkan. Penerjemah
memakainya untuk membuat `.po` (terjemahan) yang lalu dikompilasi jadi `.mo`.

Dengan WP-CLI:

```bash
wp i18n make-pot . languages/wc-bulk-editor.pot
```

WP-CLI belum terpasang di lingkungan ini. Alternatifnya, **Poedit** (aplikasi
desktop) bisa memindai folder plugin dan menghasilkan `.pot` tanpa CLI.

Alur kerjanya:

```
kode  →  .pot  →  .po (per bahasa)  →  .mo (dikompilasi)
             penerjemah          otomatis/Poedit
```

Penamaan file wajib mengikuti pola `{textdomain}-{locale}.mo`:

```
languages/
├── wc-bulk-editor.pot            template
├── wc-bulk-editor-id_ID.po       terjemahan Indonesia (sumber)
└── wc-bulk-editor-id_ID.mo       hasil kompilasi ← ini yang dimuat WordPress
```

`.gitignore` plugin ini sudah memblokir `*.mo` — file itu hasil kompilasi dan
bisa dibuat ulang dari `.po`. `.po` dan `.pot` tetap masuk repo.

Locale Indonesia adalah `id_ID`. Daftar lengkap ada di
`wp-includes/l10n.php` dan situs translate.wordpress.org.

## 6. Yang Harus Dikerjakan

Berurutan dari yang paling murah:

- [ ] **Tambah `Domain Path: /languages` ke header plugin.** Satu baris.
      Tanpa ini, terjemahan yang dibundel tidak akan pernah dimuat.
- [ ] **Buat folder `languages/`.**
- [ ] **Pindahkan 9 string hardcoded** dari `admin.js` ke `i18n_strings()`.
- [ ] Generate `wc-bulk-editor.pot`.
- [ ] (Opsional, besar) Terjemahkan 29 label kolom lewat `column_labels()`.

Tiga yang pertama bisa dikerjakan dalam beberapa menit dan langsung membuat
plugin siap diterjemahkan.

## Checklist Menulis String Baru

- [ ] Text domain literal `'wc-bulk-editor'`, bukan variabel
- [ ] String itu sendiri literal, bukan variabel
- [ ] Varian escape dipakai di view (`esc_html_e`, `esc_attr_e`)
- [ ] Placeholder `%s`/`%d`, bukan penyambungan string
- [ ] Komentar `/* translators: */` ada kalau memakai placeholder
- [ ] Penomoran `%1$s`/`%2$s` kalau placeholder lebih dari satu
- [ ] `_n()` untuk jamak, bukan `if ($count === 1)`
- [ ] String JS masuk `i18n_strings()`, bukan hardcoded di `admin.js`
- [ ] Tidak memanggil `__()` sebelum action `init`
